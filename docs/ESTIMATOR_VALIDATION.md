# Estimator validation (synthetic data)

**Everything on this page comes from simulated surveys with a known true population. No real dog is described here.** The simulator (`sim/model.py`) feeds the same `notchcount_stats` code that runs on real data.

Generated by `uv run python -m sim.run`: 1000 replicates per scenario, 400 sampler draws per replicate (the production default is 2000; percentile intervals are stable at this size), `notchcount_stats` 0.1.0, 8.6 minutes on 8 cores. Seeds are fixed, so rerunning gives identical numbers.

## What this shows

- **S1** (meets 0.93, coverage 0.930). Equal catchability, perfect matching: the reference case. Expected near 0.95; small shortfalls come from the log-normal approximation and the sampler size.
- **S2** (falls below 0.93, coverage 0.618). Dogs differ in how easy they are to see (Beta(2, 1.33) catch probability). Easy dogs are seen in both passes, so recaptures run high and Chapman runs low. This is a property of the two-sample method, not of the code, and it is why the report calls the estimate a likely lower bound.
- **S3** (falls below 0.93, coverage 0.908). One in twenty true matches scores like a look-alike. The assignment sampler lets each walk-2 dog choose one candidate or none, with likelihood ratios recovered from the calibrated probabilities and the recapture rate solved jointly, so a weak true match keeps its probability instead of losing it in a one-to-one repair. That lifts coverage well above the BIBLE pairwise sampler on the same data (S3p) and halves the bias, but it is still about 0.02 short of the 0.93 target: a small upward bias remains because some missed true matches stay missed.
- **S4** (within Monte Carlo error of 0.93, coverage 0.923). One in twenty walk-2 dogs has a look-alike scored above 0.5. The assignment sampler sometimes picks the look-alike and sometimes the true partner, and that choice is carried into the range. Coverage is within Monte Carlo error of the 0.93 target and above the pairwise sampler (S4p).
- **S5** (falls below 0.93, coverage 0.889). Few recaptures: the Chapman variance and the log-normal interval are rough at small m2, so coverage drops and ranges are wide. Some surveys have too few matches to estimate at all.
- **S6** (falls below 0.93, coverage 0.810). The same matcher as S3, but every pair is decided at 0.5 and fed to plain Chapman. Missed matches lower m2 and inflate N, and the interval knows nothing about it. This is what NotchCount would report without the sampler.
- **S3p** (falls below 0.93, coverage 0.866). S3 data with the BIBLE 3.4 pairwise sampler (independent pair draws, then greedy one-to-one repair), kept for comparison. Calibration moves a weak true match's probability onto look-alikes, and the repair discards most of it because those look-alikes already have clear partners.
- **S4p** (falls below 0.93, coverage 0.901). S4 data with the pairwise sampler, for comparison.

## Limits of this validation

- The simulated matcher is calibrated by construction. The real matcher is a logistic model fitted to the team's labelled pairs (`docs/MODEL_REPORT.md`); if it is miscalibrated, real coverage will be worse than S3 and S4.
- Each dog appears at most once per pass here. Real passes have side and head shots and repeat sightings, which the within-pass clustering must group correctly.
- Notch calls are perfect apart from hidden ears. Real notch calls go through a classifier and human review.
